# 🧙 High Wizard Invention — Advanced Reference

Use when the user genuinely needs originality, invention, or a new design direction.

## 1. Double-Diamond Rhythm

Use the innovation rhythm:

### Discover
Understand problem/user/system broadly.

### Define
Converge on the real challenge.

### Develop
Diverge across genuinely different solution families.

### Deliver
Test, reject, refine, and select.

Treat it as an iterative mental pattern, not rigid waterfall.

Source:
https://www.designcouncil.org.uk/resources/the-double-diamond/

## 2. Solution-Family Rule

Generate at least 3 materially different approaches for important invention tasks.

A solution family is different when it changes:
- mechanism,
- ownership,
- architecture,
- interaction model,
- economic model,
- timing,
- automation level,
- information flow.

Different colors/layouts are not different solution families.

## 3. Inversion

Ask:
- How would we guarantee failure?
- What makes current solutions annoying?
- What if the user did none of this?
- What if the system could not use the obvious technology?

Reverse the answers into opportunity.

## 4. Subtraction

Before adding:
- remove a step,
- remove an account requirement,
- remove a screen,
- remove a dependency,
- remove a choice,
- remove waiting,
- remove manual configuration.

Breakthroughs often come from subtraction.

## 5. Combination

Combine mechanisms from unrelated domains:
- game feedback + productivity,
- aviation checklists + consumer onboarding,
- financial ledgers + digital entitlements,
- multiplayer matchmaking + group decision-making,
- compiler validation + content generation.

Transfer principles, not protected expression.

## 6. Morphological Exploration

For complex product design, define axes:

```text
Input: manual | passive | sensor | AI
Decision: rule | score | recommendation | autonomous
Feedback: visual | audio | haptic | social
Persistence: none | local | cloud | shared
```

Combine unusual but coherent cells.

Do not enumerate hundreds of combinations; sample the most promising.

## 7. Extreme Constraints

Explore:
- 10 seconds to use,
- no login,
- offline only,
- one button,
- zero training,
- 100x scale,
- one-tenth budget.

Extreme constraints reveal simpler mechanisms.

## 8. Future-Back Thinking

Imagine the product has succeeded dramatically.

Ask:
- What capability must have existed?
- What did competitors fail to understand?
- What became the compounding advantage?
- What early architecture enabled it?

Then work backward to the smallest present-day version.

## 9. Anti-Buzzword Rule

Strip:
- AI,
- smart,
- revolutionary,
- seamless,
- personalized.

If the concept no longer sounds differentiated, it was not differentiated.

## 10. Wizard → Engineer Handoff

Every selected invention must produce:

- user problem,
- mechanism,
- why it is different,
- key assumptions,
- riskiest assumption,
- smallest test,
- architecture implications,
- implementation path,
- kill criteria.

No idea graduates to Godmode merely because it sounds exciting.

## 11. Originality / IP

Use inspiration at the principle level.

Do not copy:
- names,
- characters,
- art,
- distinctive layouts,
- dialogue,
- source code,
- proprietary mechanics implemented identically where protectable.

Create a new expression.
