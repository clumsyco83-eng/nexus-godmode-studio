# Project instructions

## Skill selection

**Select and use the relevant installed skills automatically. Do not wait to be told which
skill to use.** At the start of any non-trivial task, check the available skills and invoke the
ones that match. Naming a skill explicitly is an override, not a precondition.

Guidelines:

- Invoke a skill when its `description` matches the work, even if the user's request never
  mentions skills or names one.
- More than one skill may apply. Use them together — for example architecture plus security
  review for a new auth surface, or the QA director plus the release director before a submission.
- For substantial multi-stage work (a whole feature, migration, product, or release), start with
  the orchestration layer — `nexus-godmode-master` for the most complex or ambiguous cases,
  `godmode-v2` for ordinary end-to-end delivery — and let it route into specialists.
- Skip skills for genuinely trivial requests: a one-line edit, a quick factual answer, a small
  mechanical rename.
- Say which skills you are using and why, so the choice can be corrected.

in-pack skill for that lane and say so rather than assuming it is present.

Skills from other roots (`~/.claude/skills/`, installed plugins, built-ins such as `docx`,
`pdf`, `pptx`, `xlsx`, `skill-creator`) are in scope for automatic selection on the same terms.

## Skill layout in this repository

This repository *is* a skill pack, and it keeps two live copies of every skill:

- `plugins/nexus-godmode-studio/skills/` — **source of truth**, what the marketplace installs.
- `.claude/skills/` — a byte-identical **mirror**, generated by the
  `Sync NEXUS Project Skills` GitHub workflow. It exists so the skills load automatically for
  anyone working inside this repository without installing the plugin.

Consequences for any edit:

1. Edit the copy under `plugins/nexus-godmode-studio/skills/`.
2. Re-run the sync workflow, or apply the identical edit to `.claude/skills/`.
3. Verify with `diff -r plugins/nexus-godmode-studio/skills .claude/skills` — it must report
   no differences. Divergence is a bug, not a variant.

Never merge skill folders and never delete one to resolve the duplication — the two copies are
intentional and serve different install paths.

## SKILL.md requirements

Every skill folder must contain a `SKILL.md` with:

- YAML frontmatter beginning at the very first byte (no BOM, no blank line), opened and closed
  with `---`
- `name` exactly equal to the folder name, as a lowercase-hyphen slug
- `description` under 1024 characters, covering both what the skill does and when to use it
  (this text is the only thing skill selection sees, so it must carry the trigger conditions)
- correct relative paths for any supporting files under `references/`

Keep versions in `.claude-plugin/marketplace.json` and
`plugins/nexus-godmode-studio/.claude-plugin/plugin.json` equal when releasing.
